# 架构决策记录

架构决策记录（ADR）用于保存影响多个模块、部署方式或长期维护成本的重要决定。它重点回答
“为什么这样做”，与描述当前结构的架构文档互补。

## 何时新增 ADR

- 新建、合并或拆分独立服务；
- 改变数据库、消息队列、缓存或对象存储的职责；
- 引入不兼容 API 或消息契约；
- 改变任务路由、一致性、幂等、恢复或扩缩容模型；
- 引入会长期影响部署、许可证或安全边界的依赖。

普通实现细节、易于撤销的局部重构和单个 Bug 修复通常不需要 ADR。

## 状态

ADR 状态使用“提议、已接受、已取代、已废弃”。新决策如果取代旧决策，应互相添加链接，
不要删除旧记录。

## 命名与模板

文件名使用四位序号和简短英文标识，例如 `0002-add-gpu-capability-queue.md`。

```markdown
# ADR-0002：决策标题

- 状态：提议
- 日期：YYYY-MM-DD
- 决策者：维护者 / 团队

## 背景

## 决策

## 影响

## 备选方案
```
