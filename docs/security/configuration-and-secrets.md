# 配置与密钥管理

MediaFleet 将启动配置与运行时配置分开管理。

## 启动配置

数据库、RabbitMQ、对象存储、ZLMediaKit 和加密凭据由部署平台或密钥管理系统提供。
这类配置不能通过运维控制台修改，通常需要重启服务才能生效。

仓库中的 `.env.example` 只允许使用空值或明确占位符。真实 `.env` 不得提交；带认证信息的
RTSP URL、签名下载 URL、私钥和令牌也不得出现在配置示例、测试夹具或文档中。

`APP_ENV=production` 时，`API_KEY` 必须使用至少 16 个字符的非占位值；空值、`change-me`
和其他公开示例值会导致启动失败。生产密钥应由部署平台随机生成并注入，不应从示例值改写
出可预测的固定字符串。

共享 `API_KEY` 现在只作为迁移期部署引导凭据。控制中心可创建 `mfk_` 前缀的范围化凭据，
支持 `read`、`task:write`、`recording:write`、`node:write` 和 `admin:write`。数据库仅保存
PBKDF2-SHA256 派生摘要和随机盐，密钥明文只在创建或轮换响应中出现一次。凭据可以设置过期
时间、立即轮换或吊销；轮换后旧密钥立即失效。

受保护写请求在执行前写入 `STARTED` 审计事件，记录可信调用方、凭据、所需范围、路径和
幂等键摘要，响应完成后更新结果。审计不可用时写请求返回 503。请求体、API Key、签名 URL
和幂等键明文不会写入审计表。

控制中心通过 `CONTROL_CENTER_BOOTSTRAP_API_KEY_ENABLED` 决定共享 `API_KEY` 是否还能用于
认证，默认值为 `true`，用于首次部署和兼容升级。关闭前必须完成以下步骤：

1. 使用共享引导密钥创建至少一个包含 `admin:write` 的范围化凭据，并安全保存只返回一次的
   密钥明文；管理控制台还需要 `read`，建议管理凭据同时包含这两个范围。
2. 使用新管理凭据调用安全管理接口，确认认证、权限和凭据列表均正常。
3. 为 Recorder、Worker、内容分析和图像分析等节点分别签发包含 `node:write` 的最小权限凭据，
   将各服务的 `API_KEY` 改为对应范围化密钥并验证心跳。
4. 将控制中心的 `CONTROL_CENTER_BOOTSTRAP_API_KEY_ENABLED` 改为 `false` 并重启控制中心。
5. 验证旧共享密钥返回 401、管理凭据仍可使用、节点心跳持续更新，再从部署平台撤销旧值。

关闭时，控制中心会在启动阶段查询 MySQL。只有存在状态为 `ACTIVE`、所属调用方也为
`ACTIVE`、未过期且包含 `admin:write`（或兼容 `*`）的凭据才允许启动；否则控制中心拒绝启动，
防止永久锁死管理入口。该开关只影响控制中心对共享引导密钥的认证，不代替各节点自己的
范围化凭据迁移。

## 运行时配置

并发限制、容量阈值、重试预算、调度权重和节点排空状态，后续可以通过类型化配置注册表管理。

每个配置定义应包含稳定键、所有者、作用域、数据类型、默认值、校验约束、敏感级别、热加载
行为、版本、修改者和审计历史。

API 只暴露允许列表中的配置，不提供任意环境变量修改端点。敏感配置应保存为加密值或密钥
引用，创建后不返回明文。变更流程应支持校验、预览、分阶段发布、回滚和节点确认。

## 日志脱敏

日志必须移除 URL 用户信息，以及 `token`、`signature`、`secret`、`key` 等敏感查询参数。
不得记录带凭据的 RTSP URL、对象存储临时签名或完整 Authorization 请求头。
