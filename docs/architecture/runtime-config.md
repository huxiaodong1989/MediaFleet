# 分析服务运行时配置

图像分析和内容分析的模型连接及每实例并发额度可由调用中心管理。MySQL 的
`service_config` 保存当前发布引用，`service_config_version` 保存草稿与不可变发布版本；
`20261016_0004` 是从现有 MediaFleet Schema 升级的迁移。分析实例定期读取配置并通过节点心跳
报告应用状态。控制中心只做校验、版本发布和任务锁版，不加载模型或运行媒体算法。

可管理的配置使用 `media_platform/contracts/runtime_config.py` 中的类型化允许列表：模型
`base_url`、允许模型、超时、加密的 API Key，以及图像分析和内容分析各自的并发额度。
数据库、消息队列、目录、FFmpeg 线程数及服务密钥仍由部署平台管理，不提供任意环境变量
修改接口。模型名称归提示词版本；发布模型连接时，在同一事务中校验和更新相关提示词。

管理 API 位于 `/api/v1/admin/runtime-configs`，要求独立的 `X-Config-Admin-Key`。
模型密钥使用部署平台提供的 `RUNTIME_CONFIG_ENCRYPTION_KEY` 加密，管理 API 只返回
是否已配置。草稿使用请求编号幂等保存，发布使用修订号防止覆盖。新任务在创建事务中
锁定连接和提示词版本；已排队、执行中及重试任务沿用原版本。配置刷新失败时保留上次
应用状态并继续重试，心跳只上报错误类型。

首次启用时，先由单个迁移执行者运行 Alembic 升级，再给控制中心和两个分析服务注入
同一 Fernet 密钥。每个分析服务只选择一个实例短暂开启 `RUNTIME_CONFIG_BOOTSTRAP`，
导入现有部署参数为修订 1，确认后关闭该开关。未导入时服务继续使用原部署配置，页面
明确显示尚未发布。在线实例若尚未上报 `runtime_config_supported`，管理端拒绝发布。

图像长任务可通过 `IMAGE_ANALYSIS_CONSUMER_TIMEOUT_MS` 设置 RabbitMQ 3.12+ 的队列级
ACK 超时。现有队列默认保持 0，需由 RabbitMQ 策略设置；新队列可设置大于任务最长
执行时间的值。图像课堂并发满时消费线程等待本机槽位，避免周期性重试消息风暴。

部署验证仍需在目标 MySQL、RabbitMQ 和真实模型环境执行，特别是迁移、已有队列参数、
密钥解密、热更新回执及在途任务锁版。
